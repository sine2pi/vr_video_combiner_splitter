## 2026-06-21 - [ffprobe Consolidation & LRU Caching]
**Learning:** Sequential calls to sub-processes like `ffprobe` to query individual metadata attributes (e.g., width, height, codec, frame rate) introduce massive latency overhead due to process spawning (approx. ~150ms per spawn, totalling ~470ms). Spawning process count can be consolidated by querying multiple stream fields in a single JSON call, reducing latency by over 80%. Furthermore, wrapping this consolidated retrieval function with `@functools.lru_cache` reduces subsequent retrieval time to virtually 0 (microsecond scale), extremely beneficial for repeated split/convert/combine workflow scenarios.
**Action:** Always fetch process-bound metadata in bulk via structured output formats like JSON rather than invoking separate shell/cli tools sequentially, and use function memoization to cache static query results.
